ChurchCoin · Plan · 8 October 2026

Importing a bank statement, as a guided walkthrough

Today a CSV upload is two dense modals: a column-mapping grid, then a 100-row review table where every row needs a dropdown. This plan turns it into a short walkthrough in the same style as the cash-recording wizard (#55). The app does the reading, matching and categorising. The treasurer is asked only about what it couldn't settle, and the last screen proves nothing was dropped.

02

Design principles

Ask only what the app can't work out

Detected columns are shown as settled facts with an “edit” link, not as blank dropdowns. Steps with nothing to ask are skipped and shown struck through on the rail.

Every row is accounted for

Rows read = new + already imported + skipped (with reason) + needs fixing. If there is a balance column, the last screen checks the parsed rows against it.

Confidence decides attention

Sure matches (rules, memory) are collapsed. Likely matches get a glance. Only “needs you” rows get a card each, one at a time, with keyboard shortcuts.

Plain words, big targets

Same type scale and 46–54px buttons as the cash walkthrough. “Money in / Money out”, not “Credit / Debit”. No 10px all-caps labels.

Learn once, reuse monthly

The column layout is remembered per header signature, so next month's file from the same bank skips the columns step.

One review for bank sync and files

Yapily sync lands in the same Categorise → Check → Done steps. One code path, one mental model.

03

The new flow

Five steps and a finish. Dashed steps only appear when there's something to ask.

1

Add statement

Drop the file and pick the account. Bank-by-bank export tips are here.

2

Check columns

Confirm what was detected and see a live preview of the result.

Skipped when the layout is remembered
3

Fix rows

Fix or leave out the rows that couldn't be read, with the reason shown.

Skipped when every row reads cleanly
4

Categorise

Runs automatically. Answer only the “needs you” rows.

5

Check & import

Totals, fund split, balance proof, duplicates. One button.

✓

Done

What was added, then reconcile it or import another file.

07

Build plan

Four PRs, each shippable on its own. The first changes almost nothing visible but fixes correctness. Everything reuses the existing Convex functions. The only backend addition is the remembered-layout table in phase 3.

Phase 1 · A parser you can trust no visual change

  • New pure module lib/statementImport.ts: a real CSV tokenizer (quoted commas and newlines, "" escapes, BOM, delimiter sniffing), header-row detection (skips preamble lines, handles headerless files), scored column detection, date-order detection, and mapStatementRows() returning { rows, skipped, errors } with source line numbers and reasons.
  • Built on the existing parseImportedDate, parseImportedAmount, withImportKeys and screenImportRows, which are not rewritten.
  • Swap the bodies of handleFileUpload / handleProcessMapping to call it. Name failing rows in the confirm error.
  • Fix “Assign to Campaign” so it only sets the fund (and skips expenditure), or remove it.
  • Tests: synthetic fixtures shaped like Lloyds, Barclays, Nationwide (preamble), HSBC (headerless), CAF and an Excel export, plus every row-accounting outcome. Retire the characterisation assertions in tests/audit.importBaseline.test.ts that describe now-fixed defects.

Phase 2 · The walkthrough the main change

  • Move the shared shell from components/cashEntry/ (ui.tsx classes, rail, progress, StepFooter, receipt frame) into components/wizard/, and switch the cash wizard to import from there, so both wizards share one shell.
  • New components/statementImport/: StatementImportWizard, steps.ts (skips steps with nothing to ask), UploadStep, ColumnsStep, FixRowsStep, CategoriseStep, CheckStep, DoneStep, and a useStatementImport reducer holding the pending batch.
  • Pull the review state (pending rows, duplicates, pairing, predictions, AI run) out of TransactionManager.tsx into that hook. Bank sync enters the same wizard at Categorise. This removes roughly 800 lines from TransactionManager.
  • Categorise: auto-run categorizeWithPipeline on entry, confidence buckets from predictionSource + confidence, focus cards, group-apply, keyboard shortcuts, and “See all” for the full table.
  • Check: totals, fund split, duplicate callout, chunked bulkCreate (≤500 per call) with progress, then Done with next steps.
  • Session-storage draft so closing the tab doesn't lose a categorised batch.

Phase 3 · Less work every month schema addition

  • Remembered layouts: a new importProfiles table (organizationId, headerSignature, mapping, dateOrder, accountLabel, lastUsedAt), with a list query and an idempotent save mutation gated by requireRole. Columns step skipped on a match.
  • Balance-column check on the Check step. Pre-fill Reconcile's closing balance from the file.
  • Accept .xlsx via SheetJS (already a dependency, loaded lazily).

Phase 4 · Optional needs your call

  • “Undo this import”: add an optional importBatchId to transactions, and a mutation that voids (not deletes) a batch within N days.
  • Per-account statements (ties into “per-account rows not yet modelled” from the ledger-movements work).

Verification

Vitest for the parser, row accounting and step skipping. Drive the real app with each fixture file (the run skill on a local Convex backend, not the live dev deployment): upload → Done, check the ledger rows and balance check, then re-upload the same file and confirm “already imported” = all.

Out of scope

Changing the categorisation pipeline itself, PDF statement parsing, and new bank providers. The wizard uses the pipeline and the Yapily sync as they are today.

08

Decisions for you

1. Should categorisation start automatically?

It makes an AI call per import, even for people who would categorise by hand. Rule and memory matches are free, so only unresolved rows reach the model.

Recommend: yes, auto-run. A “Skip AI” link is enough of an escape.

2. Is a new importProfiles table OK?

It's the only schema change needed for “skip the columns step next month”. Without it, the mapping could be remembered per browser in localStorage instead, which is weaker for teams.

Recommend: the table, in phase 3.

3. One Import button? (decided)

No. A file import and a bank-feed sync are different sources, so they keep separate buttons. They share only the review steps from Categorise onwards.

4. Undo import?

Reassuring for nervous first imports, but it needs a batch id on transactions and clear rules around reconciled rows.

Recommend: defer until people ask for it. The Check step already makes mistakes rare.
