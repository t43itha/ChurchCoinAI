ChurchCoin · Plan · 8 October 2026

Every screen in the walkthrough style

The cash walkthrough (#55, #56) is the best-feeling part of ChurchCoin: one question per screen, big targets, plain words, a running total that never leaves view, and an ending that says what to do next. The rest of the app still looks like a spreadsheet with uppercase labels. This plan turns the walkthrough's parts into a shared kit, then uses it on every screen. Pages become calm hubs that show the money and what needs doing; every job becomes a walkthrough on the same shell as Record giving.

01

What makes the walkthrough work

Read from components/cashEntry/ on main (2c03147). Each of these is a choice in the code, so each can be carried to the other screens deliberately.

One question per screen

“Which services had a collection?” is the screen title, in 23px sentence case, with one line of help under it. Today's pages open with a 12.5px uppercase heading and six buttons.

The number that matters, in ink

The dark darkCard holds the one fact the screen is about (week ending). On hubs it holds the balance or total the treasurer came to see.

A running total that stays put

The Receipt column on desktop and the StepFooter total on a phone. Every hub gets the same column for its period totals.

An ending that hands off

DoneStep's “What's next” list (Bank it · tithers without Gift Aid · record another week). The same list becomes “Needs you” at the top of each hub.

Big, forgiving targets

46–54px buttons, 52px tick rows, 44px chips, 1.5px input borders, 16px radii, active:scale. Today's pages use 36px buttons with 12px uppercase text.

The same thing on a phone

Full-screen sheet below lg, centred three-column panel above it. Same tree, no separate mobile build.

Two templates for the whole app

Hub

Pages you look at

Dashboard, Transactions, Funds, Donors, Campaigns, Loans, Reports, Settings, Ask Ward.

App nav · page (title, one-line status, hero card, “Needs you”, content) · receipt column with the period's totals. The receipt column folds into the page below xl.

Walkthrough

Jobs you do

Record giving ✓, import a statement (planned), reconcile, bank cash, add a transaction, transfer, add a donor or pledge, record a loan, invite someone, set up the church.

Exactly CashEntryWizard's shell: step rail · one question · live receipt, with a sticky footer total and one primary button. Ends on a Done screen with “What's next”.

07

Build plan

One PR per phase (bigger phases split per screen). Each screen keeps its queries and mutations; only the presentation and the flow change. No schema changes are needed for any of it.

Phase 0 · Extract the kit no visual change

  • Move cashEntry/ui.tsx class strings into components/ui/: Button, Card, HeroCard, TickRow, Segmented, Chip, Tag, AmountInput, NextList, Receipt.
  • Pull the shell out of CashEntryWizard into <Walkthrough>: portal, rail, header, progress, footer, receipt slot, Escape, close-confirm, save lock.
  • Record giving uses both. Its existing tests stay green; the wizard looks identical.
  • An ESLint rule (or ratchet test, like money arithmetic) flags new uses of swiss-card, btn-primary and uppercase h3.

Phase 1 · Shell and Dashboard first thing people see

  • Grouped nav, “+ New” chooser, attention counts, bottom bar under md.
  • <Hub> template: header, hero, Needs you, content, receipt column.
  • Dashboard on the hub template, reusing buildMonthEndChecks.

Phase 2 · Jobs become walkthroughs biggest usability gain

  • Reconcile, Bank cash & cheques, transfer, link movement, the transaction sheet.
  • Statement import continues on its own plan and lands on the same shell.

Phase 3 · Money and people hubs

  • Transactions (split TransactionManager.tsx into the hub, the side panel and the existing modals' replacements as it goes).
  • Funds, Donors, Campaigns, Loans and their sheets and walkthroughs.

Decisions for you

1 · Phone navigation: bottom bar or keep the drawer?

A bottom bar (Home · Money · + New · People · Reports) puts Record giving one tap away on Sunday. The drawer keeps all nine items visible but hides them.

Recommend: bottom bar, with Settings and Ward under the avatar.

2 · Active nav colour

Today the active page is an amber pill. In the walkthrough amber means “needs attention”, so the plan uses grey with ink text for “you are here” and keeps amber for counts.

Recommend: grey active, amber only for attention.

3 · Keep a dense table view anywhere?

Day-grouped rows are friendlier, but an accountant scanning 300 rows may want columns.

Recommend: a “Compact” toggle on Transactions and Reconcile on desktop only.

4 · Where should edits happen on desktop?

Side column (as mocked on Transactions and Donors) keeps the list in view. A centred sheet is simpler to build and matches the phone.

Recommend: side column on Transactions and Donors, sheets elsewhere.

5 · Order of work

Phase 1 is the most visible; phase 2 removes the most friction (reconcile and banking are the screens volunteers struggle with).

Recommend: 0 → 2 → 1 → 3 → 4, so the hard jobs improve first.

6 · Ship behind a switch?

Each hub could sit behind a per-organisation flag so you can try it on your own church before everyone gets it.

Recommend: no flag for walkthroughs (they replace modals); a short-lived flag for the Transactions hub only.
