# Named In-Person Donations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore donor-linked named donations inside the current in-person giving cash collection flow while preserving the service totals ledger and making both tabs mobile responsive.

**Architecture:** Extend the existing cash collection mutation to accept `serviceRows` and `namedDonations`, and keep both transaction types linked by the same `cashCollectionId`. Update `lib/inPersonGiving.ts` so service transactions and named donation transactions are grouped separately for the `/transactions` In-Person Giving tab. Refactor `components/CashTakingsEntry.tsx` locally enough to support two responsive tabs without introducing a new route or table.

**Tech Stack:** React 19, TypeScript, Convex mutations/queries, Vitest, Tailwind utility classes, existing `DonorSearchInput`.

---

## File Structure

- Modify `tests/inPersonGiving.test.ts`: add coverage for mixed service rows and named donations in the same collection.
- Modify `lib/inPersonGiving.ts`: add named donation ledger types and grouping behavior.
- Modify `convex/mutations/cashCollections.ts`: accept `namedDonations`, validate them, find/create donors, and create donor-linked income transactions.
- Modify `components/CashTakingsEntry.tsx`: add tab state, named donation state, responsive service cards, responsive named donation rows/cards, totals, and payload.
- Modify `components/TransactionManager.tsx`: render expanded In-Person Giving collection details as `Service Totals` plus `Named Donations`.
- Do not manually edit `convex/_generated/api.d.ts`; it will be regenerated by Convex.
